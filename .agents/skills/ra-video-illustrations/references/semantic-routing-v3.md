# V2 修复与 V3 语义路由

## 路由顺序

每个场景先写唯一判断、语义主体、核心动作或关系、必须可见的证据，再按以下顺序选择：

1. **真实来源素材**：已授权 X 图片、用户素材、产品截图或已有本地图片与判断直接相关时，选择 `source-collage`。
2. **人物动作**：能用人的选择、观察、交接、检查、比较、受阻、创建或完成表达时，选择 `human-action`。
3. **手绘关系**：流程、层次、前后变化、开放边界或反馈闭环，选择 `handdrawn-flow`。
4. **文字主导**：分类、短结论、比较、预设列表或纯抽象概念，选择 `type-led`。
5. **抽象隐喻**：前四种都不适合时才允许；必须写明隐喻与判断的对应关系。
6. **机械结构**：只有语义主体明确是实体机器人、硬件、机械、制造业或工业设备时才允许。

素材只有“题材相近”但不能证明当前判断时，不进入 `source-collage`。转到后续模式，不为了用素材而硬贴。

## 默认机械禁用集合

V2 新 prompt 与没有实体机械例外的 V3 scene 必须包含：

`机器人`、`齿轮`、`工厂`、`机械臂`、`金属卡匣`、`电路板`、`工业流水线`、`发动机`、`机械底座`。

AI、Agent、模型、插件、工具、架构、记忆、权限、沙箱、调度和能力模块本身不构成机械例外。

实体例外按语义主体逐项开放：实体机器人可开放机器人/机械臂/机械底座；硬件可开放电路板；机械、制造业和工业设备只开放与场景直接相关的设备。没有直接关系的禁用项仍保留。

## 三类典型翻译

| 判断 | 错误翻译 | V2 修正版 | V3 推荐 |
| --- | --- | --- | --- |
| 模型只是 Agent 的一部分 | 机器人剖面、金属模块 | 扁平能力卡与人物 | `handdrawn-flow`，人物与五类能力关系 |
| 任务途中创建缺少的工具 | 机械臂安装零件 | 人发现缺口并补上一张工具卡 | `human-action`，缺口→创建→重新接回任务 |
| 事件轨迹可回查但普通用户觉得复杂 | 卡匣和轨道堆叠 | 时间线与困惑用户对照 | `human-action` 或 `handdrawn-flow`，连续轨迹对比用户负担 |

## 停止条件

V3 raster 候选 01 失败后，只允许根据失败的 semantic check 做一次定向修复并生成候选 02。候选 02 仍失败就停止；不切换 Provider、不改成 type-led、不删除失败记录、不把测试 fixture 的 pass 当作真实图片审核。

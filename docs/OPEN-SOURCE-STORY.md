# BoomEarth 开源介绍口播稿

## 成片口播稿

四毛钱，二十分钟，能不能做出一条真正可以交付的口播视频？

可以，但不是靠一个提示词，也不是随便拼几个 AI 工具。

今天我把 BoomEarth 开源了。它要解决的，是很多创作者最头疼的那一段：你有
一个视频、一篇文章、一个 GitHub 项目，甚至只有一份文稿，怎么稳定地把它变成
有开头、有观点、有插画、有配音、有字幕、有封面，最后还能通过质检的成片。

如果你也经常卡在文案、配音、字幕和剪辑之间，先点个赞，收藏一下。这个项目
不是教你多背一个 Prompt，而是把一条能反复跑的视频生产线拆给你看。

BoomEarth 最早只是一个本地视频工作台。十几天、三百多个提交之后，它已经
变成一套从来源到成片的完整合同。

本地视频、音频、可播放链接、X 图文、GitHub 开源项目，都能进入同一个工作单。
来源地址、逐字稿和平台响应全部留在私有区；公开文稿只保留重新组织后的观点，
不会把原始来源和隐私一起带进成片。

文案不是直接扔给配音。系统先判断开头有没有点题，观众能解决什么问题，前三秒
有没有钩子，再做口语化、去 AI 味和共鸣审阅。旁白锁定以后，整条视频的时间线
才真正成立。

字幕也不是按字数硬算。BoomEarth 会对最终旁白重新做词级识别，再按照中文
口语语义断句。每一帧只显示一条单行字幕，上一句和下一句不会同时挤在画面里。

画面同样不是拿一张机器人图片反复缩放。每个场景都要有和文案真正相关的小黑
插画，组件按 reveal、wipe、fade 的方式运动；字幕、标题卡和数字人都不能冒充
正文素材。

最重要的是，它不会把失败藏起来。每次外部调用都绑定输入哈希、计划哈希、预算、
零重试和零 fallback。哪一步失败，就保留哪一步的证据，下次从第一个没完成的
关口继续，不重复烧钱，也不拿旧产物冒充新结果。

你可能最关心成本。在已经有本地硬件和模型、使用本地配音、关闭 HeyGen、复用
基础素材的快线配置下，新增云端用量可以低到大约四毛钱，目标二十分钟左右出一条
基础口播视频。这里不包含硬件、电费、订阅、首次部署、复杂插画和失败重试；它是
一个可优化的生产基线，不是对任何环境都生效的神话。

最后交付的也不只是一条 MP4。锁定旁白、字幕六件套、逐场景素材、封面、联系表、
关键帧 QC 和 delivery receipt 会一起归档。只有 1920 乘 1080、三十帧、
H.264 加 AAC 能完整解码，并且画面、字幕、音频和隐私门都通过，系统才会叫它
推荐最终成片。

这就是 BoomEarth：不是一个炫技 Demo，而是一套让普通创作者也能看懂、能修改、
能验证的视频生产工程。

如果你想研究 Agent 怎么把文案、媒体、外部服务和质量门真正串起来，欢迎去
GitHub 看代码。能直接拿来用，也欢迎把它改成你自己的生产线。

## 卖点边界

“约 0.4 元、约 20 分钟”仅描述已有本地硬件与模型、关闭 HeyGen、基础素材
复用、外部价格不变时的基础口播快线目标。公开传播时必须同时保留适用条件，
不得改写为无条件承诺、全流程统一价格或交付 SLA。

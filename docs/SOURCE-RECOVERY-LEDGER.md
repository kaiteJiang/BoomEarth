# 来源修复经验账本

新来源任务先查本页同类型最新的“完整验收”记录，再读相应 Skill 与实际采集代码。只记录可公开的通用方法、修复和离线回归；原 URL、正文、作者、仓库私有标识、Cookie、响应和完整失败日志留在忽略的私有 work item。一次 HTTP 成功、浏览器能打开、计划存在，都不算完整验收。

## 当前已实现的基线方法（不是跨项目成功回执）

| 来源 | 方法与验收 | 失败后的下一步 |
| --- | --- | --- |
| X 图文 | `ra-x-article-import` 的正式 `article_ready`、正文/JSON/图片/manifest 哈希 | 先诊断原响应和结构，离线修 parser/transport，回归后新事务采集；浏览器只作结构诊断或经过正式导入合同的补充 |
| GitHub | `ra-github-skill-import` 的固定提交、完整树、目标 Markdown 与 manifest；已有 REST→直连→只读 Git 方法梯 | 按真实错误跳方法，修补并测回归；仍缺文件时只读浏览器定位、补同一提交并重新验收 |
| 视频 URL | `katerj-source-acquisition` 的可解码私有媒体、音频和 manifest | 优先修 yt-dlp/平台提取，按新的计划尝试下一受支持方法；完成来源转写后才写稿 |

## 完整验收后追加一条

| 日期 | 类型/症状类别 | 根因与修复位置 | 最新成功方法及适用条件 | 离线回归 | 完整性 gate |
| --- | --- | --- | --- | --- | --- |
| （成功后填写） | （不写私有标识） | （代码路径/修复要点） | （方法、平台条件） | （命令与结果） | （article_ready/media_ready/github_skill_ready 等及哈希验证） |

同类型多条记录按日期倒序选最近**仍通过回归和完整性 gate**的方法。新故障只追加，不覆盖旧条目；如果修复改变路线，更新相应 Skill、采集代码和测试，让新会话自动走最新有效路径。

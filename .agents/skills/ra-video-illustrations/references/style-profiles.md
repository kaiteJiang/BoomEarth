# 风格选择

| 内容信号 | visual_type | visual_style |
| --- | --- | --- |
| 观点、趋势、人物状态、抽象隐喻 | concept-scene | editorial-scene |
| AI 工具、教程、操作流程 | framework | minimal-vector |
| 系统、Agent、架构、数据流 | 先按真实主体和关系选择；必要时 technical | 扁平关系图或 technical-diagram，不默认机械材质 |
| 强冲突、前后反差、反常识结论 | comparison | screen-print-metaphor |
| 授权截图、产品图、人物或现有素材 | clean-collage | clean-collage |

保持单一焦点。framework/technical 最多 3–5 个对象、三条主路径；超过就拆场景。相邻场景保持材质和色板连续，不随机换风格。

## V2 修复

`technical-diagram` 的含义是关系清楚，不是机械剖面图。AI、Agent、模型、插件、工具、权限、沙箱、记忆和调度场景优先使用人物工作状态、扁平卡片、门禁、清单、时间线和轻量连接线。只有文案明确讨论实体机器人、硬件、机械、制造业或工业设备时，才允许对应机械对象。

## V3 模式与风格

| visual_mode | visual_style | 适用证据 |
| --- | --- | --- |
| source-collage | semantic-collage | 已授权素材与当前判断直接相关 |
| human-action | semantic-handdrawn | 人在选择、检查、创建、交接、受阻或完成任务 |
| handdrawn-flow | semantic-handdrawn | 层次、路径、反馈、前后变化或边界关系 |
| type-led | semantic-type | 分类、短结论、比较和抽象概念更适合精确文字 |

V3 采用纯白或浅色留白、黑灰手绘线、受控淡彩标签和一个主关系。`type-led` 由 renderer 绘制，不是生图失败的回退。

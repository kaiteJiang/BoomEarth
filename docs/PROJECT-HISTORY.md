# BoomEarth 开发历史与架构演进

## 项目概览

BoomEarth 从 2026-08-09 的第一份本地视频工作台方案开始，到本次公开准备前
累计 303 个提交。项目没有把“生成一段视频”当作完成，而是逐步把来源授权、
隐私隔离、不可变计划、真实音频字幕、视觉语义、失败恢复和最终归档变成可以
验证的生产合同。

## 演进时间线

### 2026-08-09：V1 本地工作台

最初目标是建立一条本地优先链路：授权媒体进入私有区域，经过内容处理、本地
IndexTTS2、HyperFrames 和 QC 后归档。同期确定 `.env`、运行时媒体和源材料
不得进入 Git。

### 2026-08-11 至 08-12：真实音频与字幕边界

项目补齐 live smoke 的显式授权，建立 V2 生产验收样例，并把最终旁白 WAV
设为全片唯一时间轴。来源转写与最终字幕被拆成两个独立阶段；最终字幕必须对
锁定 WAV 做词级 ASR，不能再用脚本长度估时。

### 2026-08-13：来源到交接稿、内容驱动渲染

本地文件和 URL 进入统一私有 work item。无来源交接稿只能由编译器发布，
publication receipt 与 ledger 同时通过才允许交给制作端。内容计划、场景时间线、
字幕六件套、联系表和 delivery checker 形成闭环。

### 2026-08-14：横版生产、X 图文、语义插画和运动

来源比例与成片比例正式分离，最终画布统一为 1920×1080。X 图文拥有独立的
私有采集路线；画面从静态文字卡演进到逐场景语义插画，并加入组件级 reveal、
wipe、fade 和 settle 运动证据。

### 2026-08-15：GitHub 解读、V4 主题、黑金声线和数字人

GitHub Skill/仓库 URL 获得只读采集入口，明确禁止安装、执行仓库代码或下载
归档。视觉扩展到注册主题库，本地黑金 v3 成为规范声线；HeyGen 只负责使用
同一锁定旁白生成口型 master，本地再合成为左下角圆形头像。

### 2026-08-16：真实平台来源与上线加固

Bilibili、yt-dlp 和 TikHub 路线加入分阶段授权、媒体校验和失败停止边界。
生产检查开始覆盖 Windows 路径安全、原子归档、不可覆盖发布和隐私诊断。

### 2026-08-22 至 08-24：可恢复生产、封面和字幕体验

生产端可以从既有 Provider 结果恢复，不因阶段失败重复收费。3:4 Punk 作品
封面纳入默认交付；字幕增加中文口语断句、同音词纠正、单行显示和逐帧互斥。

### 2026-08-26：KaterJ Skill 真源

18 个外部来源的长入口被重新设计为 BoomEarth 自有的 `katerj-*` 真源 Skill。
旧名保留为薄兼容桥，因此历史交接稿、命令和自动化仍能工作。仍被依赖的第三方
脚本、字体或素材继续保留原许可证，不被冒充为 KaterJ 原创。

## 今天的系统边界

```text
Source plane   私有输入、下载、来源媒体、来源转写
Writing plane  source-free 改写、钩子、口语化、审阅
Media plane    逐场景插画、本地 TTS、最终音频字幕、可选数字人
Render plane   组件运动、字幕烧录、16:9 合成
Evidence plane manifest、SHA-256、联系表、QC、delivery receipt
Archive plane  已制作/<月上旬或下旬>/<日期-主题>
```

这套分层的核心价值是：任何一步都不能用“看起来已经完成”代替证据。计划不是
产物，候选图不是已批准素材，进程存在不是旁白完成，MP4 能打开也不等于通过
字幕、画面、音频和隐私 QC。

## 验证基线

- KaterJ 迁移专项：39 项测试通过。
- 18 个 `katerj-*` Skill：全部通过官方 Skill 结构校验。
- 当前树与完整 Git 历史：未发现高置信 Token 或私钥。
- 默认测试不联网；真实 Provider 调用需要独立、精确、可审计的批准。

历史归档可能绑定已经退役的本地私有音色文件，因此某些仅在原作者机器存在的
保留归档验收，不应被误解为公共安装的必要条件。

# 海绵版连续制作编排

本页由 `AGENTS.md`、`ra-source-to-video` 和制作 runbook 引用；新会话从项目文件和回执恢复，不依赖旧聊天。用户只要求出文稿时，完成来源采集、事实核查和全文稿审阅即停；用户已定稿并要求制作视频时，继续到正式成片、质检、归档和封面。任何阶段以真实文件、哈希和 gate 为准，不以进程启动或计划存在代替完成。

## 一条主链

1. 判别输入：X 图文、X/其他视频、GitHub 仓库、本地媒体、直接文稿或已有项目。建立或恢复唯一 work item，核对 production note 和私有 ledger。来源内容保持私有，仓库只读。
2. 采集完整来源并验收：文章正文/图片，或可解码媒体/来源转写，或仓库固定提交/完整树/目标文档。失败进入下方恢复环，不把失败写成“已采集”。
3. Astra 写稿并核对事实、逻辑和个人口吻；新稿套用固定开头结尾；提交用户审阅。批准后锁定全文与 SHA-256，不擅改字词。
4. 导演建立场景、语义插画、动作、字幕安全区与旁白合同。插画与本地 IndexTTS2 在合同确定后并行；图片要逐场有真实生成回执、原生文字和语义 QC。
5. IndexTTS2 最终 WAV/manifest 全部验证通过后，才用**这份 WAV** 做一次真实词级 ASR；按 `jl-oral-linebreaks` 的闭合语块规则切单行字幕，检查标点、长度、词时间、SRT/VTT 六件套。
6. 依据真实音频和字幕时间定场景/组件 cue，正式渲染；逐场景、关键词 cue、联系表、完整解码和 delivery 检查全过后归档。封面按视频 3:4 合同另做。更新 note 的下一步；不自动向平台发布。

## 来源失败后的自修复环

每次失败先保留原计划、回执、响应诊断、文件和 ledger；按**网络/限流、鉴权或权限、重定向、结构解析、媒体解码、预算/截断、哈希/发布**分类。优先检查目标 URL 是否仍有效、缺的是哪些内容、是否已经有可恢复的成功响应。不要凭标题、仓库名或浏览器可见的一小段内容写“原文”。

先读取 [来源修复经验](SOURCE-RECOVERY-LEDGER.md)，按同来源类型最近一次**完整验收**的路径尝试。故障可复现时，先用私有缓存或最小样本修 parser/transport/下载适配器，加入能复现此故障的离线回归；测试通过后创建**新 work item + 新不可变计划/回执**，或执行该来源专门定义的恢复 gate。旧事务的零重试/零回退承诺不可原地修改。一个方法不通就基于故障换下一个受支持的只读方法，记录物理请求数、预算及方法。浏览器可以用于定位真实网页结构和补充只读证据；只有经过现有完整性、同版本/同提交和哈希合同的材料才能成为正式来源。GitHub 遵循 REST→直连→Git 读取；视频优先 yt-dlp，失效则诊断网页/提取器，修复后重采，必要时按新计划换受支持来源；X 图文修解析器并用正式 article gate 验收，不用正文残片代替。

每次修复并**成功取得完整正式快照**后，在经验账本追加“症状类别→根因→修复位置→回归命令→成功方法→适用条件→完整性证据”，下一次先复用该路径；若后来失效，追加新条目，不抹去旧诊断。只把不含 URL、作者、正文、Cookie、私人路径的通用经验写进 Git；细节留在 `.internal/洗稿/<work_id>/`。遇到真实权限障碍、来源删除、所有可用只读方法不可达或预算不足时，保存缺口和唯一下一步，向用户报告需要处理的事项；不要无限空转或反复扣费。

## IndexTTS2 的并行与 30 分钟节拍

旁白合同 dry-run 通过后，仅启动一次本地生成；在 production note 记录启动时间、进程/日志的**私有位置提示**、已批准脚本 SHA、segment 数、下次检查时间。若运行会跨当前对话，在当前任务设置每 30 分钟唤醒的 heartbeat，提示读取此 note；每次检查后更新时间，成片或失败后停止 heartbeat。配音进行时继续做语义插画、逐图 QC、场景文本与无音频依赖的动作准备、封面构思；这些可并行，最终 cue/ASR/渲染必须等最终 WAV。

未到 30 分钟，不轮询、不读取进度日志、不重启。到点只查一次：进程是否仍活着、私有临时目录 `raw/segment-*.wav` 的已完成数量与合同总数、是否有明确异常、是否已有最终 `narration.wav` 和 `voice_manifest.json`；按“已完成 x/y 段、运行中/异常/候选完成”向用户简报。临时片段数量只作进度，不作完成证据。若仍正常运行，记录下一次检查时间，继续其他工作或安静等待下一次唤醒。若异常，保留原始日志和临时目录，诊断并修复，禁止盲目重复启动。

只有最终 WAV 可完整解码、为 PCM、SHA 与 manifest 匹配，voice ID/provider/reference/segment 合同/1.12 倍速度及 provenance 全部通过既有 `katerj-local-tts` 验证，且无 fallback，才标记配音完成并停止检查。之后从词级 ASR gate 接续，不重合成已验收音频。

## 字幕展示合同

先按 `jl-oral-linebreaks` 的“语义闭合→长度→保护专名/数字/否定与核心动宾→口播节奏”找安全边界；短字幕以 6–12 汉字为主，14 字以上逐条复核，英文完整句和不可拆专名可例外。有时间轴时只用真实词边界，不估算时间，不改定稿字词。句中逗号（中文或英文）在同一条字幕内显示为**一个空格**；落在字幕边界的逗号不显示。行尾仅保留问号 `？` 或 `?`，其余标点删除；版本号、小数点、英文产品名内部符号不因标点规则被破坏。SRT、VTT、JSON 与视频渲染共用这一展示文本。只给少量核心词加底色，不要每句都强调。
